# 寻鹿桌面端加载体验：GitHub 调研与改造方案

日期：2026-10-09。基线：桌面恢复版 0.2.27，提交 `0443ee7`。

本轮完成公开仓库/官方文档调研、LDRS 实际预览与本地代码审计；未安装依赖，未修改应用代码，未重新打包或发布。下列时序与视觉参数是针对寻鹿的建议，尚未实施和验收。未声称飞书或 QQ 使用这些开源库。

后续实施状态：用户确认后已完成本地改造；详见 [加载体验实施与验收](desktop-loading-implementation-20261009.md)。下文保留调研阶段的原始判断，不代表当前代码仍未修改。

## 结论

以 Semi Design 的状态组织方式为参考，采用 LDRS Ring 的细线圆环风格和 React Loading Skeleton 的原位占位原则。保留页面现有排版和寻鹿青绿色品牌，只完善加载、刷新、授权交接和错误恢复的连贯性。

首选在现有 React/CSS 体系内封装共享组件；只需要一种圆环和少量占位基础形状，不必因此引入整套 UI 或重型动画运行库。如直接复用第三方源码，应同时保留对应版权及许可文件。若决定安装库，另行验证 React 19、Next 静态导出与 WebView2，不把本次文档调研视为兼容性测试。

## 本项目现状

- `public/desktop-splash.html` 的原生启动页已有圆环与减少动态支持；React 启动页在 `components/desktop-login-screen.tsx`，两阶段需要统一位置、文字层级及交接，避免重复启动感。
- `components/native-login-panel.tsx` 是当前 D1 桌面真实登录路径；等待授权主要表现为按钮里的旋转图标和文字，应改成明确的浏览器交接状态。不能只美化已经不用的旧登录表单。
- `components/desktop-home.tsx` 的申请加载状态及通知页有各自的手写结构；样式散落在桌面 CSS 文件中。
- `app/me/page.tsx` 的 Suspense 兜底只有一张居中文字卡片，没有体现日程与导师页面的结构。
- 更重要的是，日程与导师列表的空态分支主要按数量判断，未把首次远端同步 readiness 作为空态前提（`app/me/page.tsx:323`、`components/desktop-schedule-workspace.tsx:917`、`components/desktop-contacts-workspace.tsx:915`）。静态审计显示存在“尚在加载却先显示没有数据”的风险，应优先补齐首次加载/真实空结果区分；不能仅更换图标。
- `components/desktop-login-screen.tsx:53` 的慢响应计时只依赖 phase；同阶段点击重试后没有重建八秒计时。应让每次重试重新开始计时，并验证错误不会被重新变成无限等待。
- `components/desktop-app-shell.tsx` 的资源、帮助异步组件兜底主要是标题和说明；部分动态组件没有专属加载占位。
- 已有 `components/desktop-state-surface.tsx`，支持局部、完整和行内状态及 `aria-busy`，应复用和扩展。
- 当前依赖没有专用动画/骨架屏库。系统减少动态偏好和应用内减少动态设置已有基础，新增组件须同时遵守。
- `tests/desktop-loading-state.test.ts` 有禁止旧骨架结构的历史断言；新的需求应更新为布局稳定、状态正确与可访问性的行为约束，不直接恢复已废弃的旧结构，也不简单删除测试。

## 按场景实施

| 场景 | 建议表现与行为 |
| --- | --- |
| 冷启动与会话恢复 | 静态寻鹿标志、紧凑品牌区、细线圆环、真实阶段文案。只在确实阻塞进入时显示完整启动态；原生页与 React 页衔接时不跳位 |
| 系统浏览器登录 | 明确区分等待授权、收到回调、正在同步账号。保留当前账号隔离与登录时限规则；失败停止等待并提供重试，不模拟假的阶段或百分比 |
| 首次通知、申请加载 | 保留侧栏、页标题和可用筛选框；仅待加载卡片内部显示头像、标题和字段占位。占位与真实卡片共享布局尺寸 |
| 院校通知统计同步 | 保留当前已可用的院校目录及行内同步提示，统一其尺寸与动效即可。只在确实没有内容时占位，不把可操作目录换成整页骨架 |
| 首次日程、导师加载 | 分别使用日程分组行、导师联系行的真实结构占位，不把两种页面都变成通用居中文字卡片 |
| 资源、帮助、设置 | 本地静态内容就绪后直接展示；代码分块尚未加载时保留对应布局，不添加人为等待或虚假的云端同步文案 |
| 已有数据时刷新 | 保留旧内容、筛选条件与滚动位置，只在标题或工具栏显示小型刷新状态，不退回整页骨架 |
| 保存与操作按钮 | 图标区域显示小圆环，按钮宽度固定、阻止重复提交；成功或失败依据实际返回结果显示 |
| 慢网、离线与失败 | 慢请求保留上下文并解释等待；明确失败后停止循环动画，显示原因与局部重试。有缓存时标注缓存，不伪装最新数据 |

## 建议的统一视觉与时序

- 动态采用品牌青绿，骨架采用低对比中性灰；分别适配明暗主题，不在骨架上铺满高饱和品牌色。
- 按钮指示器约 16–20px，局部状态约 24–28px，启动指示器约 28–32px。具体值沿用现有字号、控件高度和缩放设置校准。
- 轻量请求可延迟约 150–200ms 显示动画，减少闪现；布局占位可立即保留。绝不为播放动画延迟真实内容出现。
- 内容就绪采用项目现有约 167ms 的透明度过渡，不逐张弹跳，不移动整片页面，不引入大面积模糊或彩色光效。
- 骨架如需动画，限制低对比、缓慢循环；同屏不要同时叠加大圆环、进度条和闪光占位。
- 系统 `prefers-reduced-motion` 或应用内减少动态启用时使用静态占位与文字；避免隐藏所有加载反馈。
- 局部容器提供 `aria-busy`，单一简短 `role=status`；装饰占位不逐项朗读。错误与长时等待分别处理，不反复抢焦点。
- 动画资源随安装包本地提供，不依赖外部 GIF、在线脚本或远程素材请求。

## 实施顺序与验收

1. 统一加载基础组件、状态文案、尺寸和减少动态规则；复用 DesktopStateSurface，整理冲突样式，避免再追加一层覆盖。
2. 优先接入启动与真实原生授权交接，再覆盖通知、院校、申请、日程和导师。
3. 补齐资源、帮助、设置代码分块兜底及行内保存/刷新反馈。
4. 用延迟、失败、断网、有缓存、真正空结果和快速请求测试验证，不通过改真实账号数据制造加载效果。
5. 验证 960/1280/1440 宽度、用户缩放、明暗主题、两种减少动态开关：无内容重叠、占位与内容跳变、焦点丢失或重复提交。
6. 完成静态导出与原生 WebView2 验证后再生成下一候选版本；保留已经交付的 0.2.27 安装包，不覆盖不可变产物。
