# 寻鹿桌面端 QQ 对标审查 v0.2.3

## 结论

本次对照使用本机 QQ 9.9.21-39038 安装目录和 `application.asar` 的文件清单、窗口行为、设置页截图与现有寻鹿桌面端代码。QQ 的 `application.asar` 标记为 `isByteCodeShell: true`，关键 renderer、preload 与主进程代码是加密/字节码形态，不能把 QQ 私有源码或素材直接复制到寻鹿；本次只借鉴可验证的交互模式，并用寻鹿自己的数据模型与品牌实现。

对寻鹿最有价值的 QQ 模式不是聊天内容，而是“高频对象列表 + 即时反馈 + 低打扰菜单”：

| QQ 模式 | 寻鹿现状 | 本版适配 |
| --- | --- | --- |
| 左侧高频入口、未读角标 | 已有 QQ 式图标轨与提醒中心 | 修正“日程提醒”入口的未读角标，使角标出现在日程入口，而不是不存在的 `today` 入口 |
| 列表对象的右键菜单、键盘菜单键 | 申请行只有双击与方向键 | 增加右键、Shift+F10、键盘 Context Menu，以及行内 `…` 入口；菜单包含打开详情、重点标记、继续准备材料、复制名称、刷新数据 |
| 最近搜索 | 全局命令面板已有搜索，但关闭后没有历史 | 增加按正式账号隔离的最近 5 条搜索；重开 Ctrl+K 可直接回搜 |
| 头像/账号入口 | 已有账号菜单、退出登录与设置 | 保留现有安全门禁；多账号切换暂不伪造，待认证服务提供账号列表后再做 |
| 设置侧栏分组 | 已有常规、通知、外观、关于 | 维持四类分组，继续采用即时生效、真实系统状态与焦点恢复 |
| 托盘、关闭隐藏、窗口状态恢复 | Tauri 已有托盘、关闭隐藏、位置/尺寸恢复 | 保留现有实现；后台定时通知和自动更新仍不在本版本承诺范围 |
| 拖动手柄、批量拖放 | QQ 资源包含 drag-handle，但申请排序没有稳定数据模型 | 不开放申请阶段拖放；继续遵守“有键盘替代和撤销后再开放”的边界 |

## 本版已落地

### 申请列表上下文菜单

申请行现在支持鼠标右键、键盘 `Context Menu` / `Shift+F10`，以及悬停出现的 `…` 按钮。菜单为固定定位，不被双栏滚动容器裁切；打开后将焦点放入菜单，方向键、Home/End、Esc 均可用。

重点标记使用现有 `priorityLevel` 字段，成功后乐观更新并同步到当前账号；列表会显示绿色“重点”标识，不新增黄色视觉语言。

### 全局搜索历史

命令面板会以 `userId` 隔离保存最多 5 条搜索词。退出登录或切换账号时不会读取上一账号历史；受限存储失败也不会阻断搜索和路由。

## 暂缓能力

- 多账号快速切换：当前认证层没有“已登录账号列表”和安全切换 API，直接照搬 QQ 会制造假入口。
- 后台退出后定时通知：Tauri 当前通知插件只保证运行期间请求横幅，不能在 UI 中提前承诺 QQ 式后台调度。
- 申请列表拖拽排序：后端没有排序字段、冲突合并和撤销协议，先不把拖动做成不可逆操作。
- 自动更新：尚未接入签名更新服务，设置页不显示“立即更新”假按钮。

## 验收

- `tests/desktop-qq-benchmark.test.ts`：QQ 对标的搜索历史、右键/键盘菜单、固定定位与减少动态效果契约。
- `npm run typecheck`、相关 ESLint 与新增 Vitest 均通过。
- 未修改或重新打包现有 Windows 安装包。
