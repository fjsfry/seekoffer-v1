# 寻鹿 SeekOffer 桌面端

寻鹿桌面端复用网站现有的 Next.js、Supabase 账号与业务数据，但使用独立的 Windows 应用壳层。桌面端必须使用正式账号登录；匿名会话和本地游客状态都不能进入应用。

## 产品结构

- 工作台：首页主线，集中列出当前账号的全部申请项目，并提供搜索、范围、类型、状态和排序筛选。
- 我的一天：作为日程与待办支线，承接当天需要处理的节点。
- 通知库：浏览公开招生通知并把目标项目加入工作台。
- 日程：管理申请相关日期与个人安排。
- 工具：进入 GPA、材料、导师联系等辅助能力。
- 全部功能：通过 `Ctrl+K` 继续访问网站已有的院校、竞赛、资源、经验与帮助页面，不扩张常驻导航。

项目详情在宽窗口中固定显示在右侧；窗口宽度不超过 1440 CSS 像素，或界面缩放达到 150% 及以上时，会自动变成带遮罩、焦点约束和 Escape 关闭能力的抽屉。

## 登录与数据

- 首次启动和无有效正式会话时直接显示桌面登录页。
- 支持邮箱密码、邮箱验证码、注册、密码重置与会话恢复。
- 匿名账号不能通过桌面门禁。
- 申请记录和手动项目缓存按正式账号 `userId` 分区，并在载荷中记录 owner。
- 旧缓存只有在全部记录明确属于当前账号、手动项目引用完整时才允许迁移。
- 账号在同步途中发生切换时，旧任务会中止，避免把旧账号结果写入新账号空间。

## Windows 能力

- 无边框标题栏、拖动、双击最大化/还原、最小化、最大化与关闭。
- 窗口位置、尺寸和最大化状态恢复。
- 原生 WebView 缩放：80%、90%、100%、110%、125%、150%、175%、200%。
- `Ctrl++`、`Ctrl+-`、`Ctrl+0` 与底部状态栏缩放菜单。
- `Ctrl+K` 快速前往，`Ctrl+,` 打开设置。
- 外部链接交给系统默认浏览器。
- 可选开机启动。

## 通知边界

提醒中心从当前账号的真实申请记录生成截止、材料和通知变更提醒，支持分类开关、已读、全部已读、30/60/180 分钟稍后提醒、安静时段和临时暂停。

当前 Windows 通知插件只负责即时横幅，不支持可靠的系统级定时、更新或取消。因此本版采用明确边界：

- 寻鹿运行期间，每 30 秒检查一次到期事件，并对新横幅做账号级去重。
- 截止、材料、通知变更和稍后提醒都经过同一运行时台账。
- 安静时段和临时暂停会真正阻止运行中的横幅请求。
- 应用完全退出后不会继续定时提醒；设置和文案不会承诺该能力。
- Windows 是否最终显示横幅仍受系统通知和勿扰设置影响。

## 设置

设置是左侧底部独立入口，不增加第六个业务导航项：

- 常规：启动目标、开机启动。
- 通知：Windows 横幅、测试通知、提醒类型、稍后时长、安静时段、临时暂停。
- 外观：浅色绿色/白色主题、舒适/紧凑密度、缩放、减少动态效果。
- 关于：版本、快捷键、帮助、协议和设置恢复。

## 本地开发

```powershell
npm install
npm run desktop:dev
```

仅在浏览器中预览桌面界面：

```powershell
npm run dev:desktop -- --hostname 127.0.0.1 --port 3000
```

## 构建 Windows 安装包

正式桌面构建需要提供网站使用的公开 Supabase 客户端配置：

```powershell
$env:NEXT_PUBLIC_SUPABASE_URL = '<public project url>'
$env:NEXT_PUBLIC_SUPABASE_ANON_KEY = '<public anon key>'
npm run desktop:release
```

安装包生成于：

```text
src-tauri/target/release/bundle/nsis/寻鹿 SeekOffer_<版本>_x64-setup.exe
```

桌面生产导出使用 `.next-desktop`，开发缓存使用 `.next-desktop-dev`，不会运行网站正式构建前的数据同步脚本，也不会覆盖 `.next-web`。

## 整理内部测试包

`npm run desktop:release` 已同时完成无密钥前端/Rust 编译、最小权限签名 bundle、公钥验签和内部包整理；无需再次单独运行打包命令。

输出目录：

```text
releases/seekoffer-desktop/v<版本>-internal-test/
```

- `public/`：规范命名的安装包、SHA-256、发布说明和安装说明。
- `internal/`：构建清单、设计 QA 报告与最终对照截图。

## 发布前事项

当前桌面端已接入 Tauri 签名自动更新、托盘常驻和关闭到后台；v0.2.5 及更早版本仍需手动安装一次带更新公钥的桥接版。内部测试包尚未配置 Windows Authenticode 组织代码签名，应用完全退出后也不会继续执行提醒调度。正式公开分发前还需要完成签名密钥离线备份，并回归 Windows 横幅、开机启动、跨版本自动更新、覆盖安装、卸载残留和真实账号跨设备同步。
