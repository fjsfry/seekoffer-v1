# 支付生产验收闸门

## 自动检查的边界

`Payment production preflight` 每小时运行一次，只验证：

- Worker 健康状态与 D1 资源目录可读；
- 未签名的 JianPay 回调会被拒绝；
- 不创建订单、不请求支付平台、不扣款。

自动检查通过，不等于真实支付已经完成验收。支付渠道的签名、异步回调、重复回调、金额校验和权益发放必须通过一次受控的小额真实交易确认。

## 一次性人工验收

1. 使用运营测试账号和可撤销的最低金额商品，记录商品、订单号、金额和测试时间。
2. 在生产站点完成一次真实支付，确认支付平台显示成功。
3. 在后台“支付监控”确认订单进入 `fulfilled`、支付进入 `succeeded`，并且收到 `payment_succeeded` 回调事件。
4. 刷新资源权限，确认只发放一次；重复刷新、重复回调不能重复发放。
5. 核对金额、商户订单号、用户和资源商品完全一致，再执行退款或关闭测试订单。
6. 将订单号、回调时间、结果和退款凭证写入发布记录；任何一项不满足时，立即关闭 `PAYMENT_PROCESSING_ENABLED`，不要手动改 D1 状态。

## 异常处置

- `needs_review`、`create_unknown` 或超过阈值的待支付订单，只能先查支付平台原单，再决定关闭、退款或补发。
- 不允许通过浏览器直接修改订单、支付或权益表。
- D1 返回 402 时，支付预检和通知同步都应停止写入；等待额度窗口恢复后由定时任务重试。
